# 这个 Prompt 在做什么？

这份材料最值得看的地方，不只是它把一个数学命题交给模型，而是它同时规定了“证明必须达到什么标准”和“模型应该怎样组织搜索”。前半段是数学任务，后半段更像一份多智能体研究流程的操作手册。

## 1. 先把数学目标锁死

Prompt 先给出复矩阵 (A) 的数值域 (W(A))，再要求对任意复多项式 (p) 证明

\[
\|p(A)\|_2 \leq 2\max_{z\in W(A)}|p(z)|.
\]

它还给出了“闭包后的数值域是 (A) 的 2-谱集”这一等价说法。这样做的好处是，模型不能把任务改写成泛泛的“讨论这个猜想”，而必须回到一个可以逐行检查的数学不等式。

同时，输出格式也被锁定为一个可编译的、全英文 LaTeX 文件。路径要求本身不影响数学正确性，但它让任务有一个非常具体的交付物。

## 2. 用硬条件阻止“看起来像完成了”

Prompt 明确说，归约到另一个未证明猜想、只做有限参数的计算、或者给出没有证明凭证的候选反例，都不算完成。这几条其实是在防模型最常见的几种“提前收工”方式：把原问题换成一个同样困难的问题，把实验结果当成一般定理，或者把一个有希望的构造写成已经成立的结论。

它还要求最终证明经过对抗性审查，检查缺口、隐含条件、含糊表述和循环论证。换句话说，证明不是“写出来”就结束，而要把每个关键引理的依赖关系摊开来检查。

## 3. 后半段是搜索编排，而不是数学定理

多智能体部分要求一开始就保留多条互不相同的路线，例如不同表述、不变量、代数视角、分解、嵌入、极值论证和计算检验；如果很多路线最后都落到同一个方法族，就要把一部分智能体重新引向尚未探索的方向。

这里有一个很重要的判断标准：优雅的归约不等于接近完成。如果某条路线最后只得到一个和原问题同等强度的缺失引理，它就应该被标记为受阻，除非出现了全新的机制或构造。这个要求对于数学证明尤其重要，因为很多错误证明恰恰是在“关键一步显然成立”处隐藏了原问题本身。

## 4. 这个设计的优点和边界

优点是标准清楚。它把“证明”“部分进展”“计算支持”“研究路线”和“对抗审查”区分开了，也提醒模型不要因为第一批方案失败就随便输出一个总结。从研究工作流的角度看，这比一句“请证明这个猜想”更能约束输出质量。

边界也很明显。Prompt 可以要求模型持续搜索，却不能凭空创造新的数学事实；“假定存在完整肯定性证明”可以防止模型过早宣称任务不可能，但也可能让模型把这个前提误当成证据，持续为错误路线寻找补丁。多智能体可以增加视角和审查次数，却不能替代关键引理的真实证明。没有资源预算、停止规则和外部专家复核时，“继续搜索”也可能变成无止境的循环。

因此，阅读这份 prompt 时，最好把它看成“证明搜索的流程设计”，而不是证明本身。任何模型返回的 LaTeX 文件，都需要独立检查定义、量词、边界条件、算子范数估计和每个引理的来源，不能因为格式完整、篇幅很长或写了“adversarial audit”就直接接受。

## 5. 这份仓库的定位

本仓库公开的是原始 prompt 的双语阅读材料和这份结构分析，不声称已经解决其中的数学问题，也不把 prompt 中“假定存在完整证明”的任务前提当作数学事实。读者可以先看 PDF 的中英双栏版本，再在 Markdown 中搜索原文，最后对照分析文件理解它的任务拆分和风险边界。
